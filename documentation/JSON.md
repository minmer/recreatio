# JSON for every part

Every part of Recreatio that holds content can be exported and imported as one JSON document — by hand, from a
backup, or prepared by an assistant. The rules are the same everywhere (2026-10-29):

- **One panel** (`ui/JsonPanel.tsx`): export, import with the list of changes and warnings before the import
  button, and the description of the format beside it — copyable for an AI, with samples to insert.
- **The description is the format's tree** (`core/jsonTree.ts`): each node says its own keys and names the formats
  inside it. The same text is served to assistants over MCP (`list_import_formats`, `get_import_format`, MCP.md),
  generated by `frontend/scripts/import-formats.mjs` into `backend/Api/Library/ImportFormats.json`; `app-json-check`
  fails when that file lags behind the app.
- **Import changes in place**: what carries an `id` from an export is updated, what has none is created; nothing is
  deleted unless the format names a previewed way to remove. References inside a document use `"@key"`.
- **Sealing does not change**: an import saves through the same functions as the part's own editor — names, titles,
  notes are sealed in the browser. The exported file is plaintext; it is the user's own download.
- **How the data is used** (2026-10-30): every description has a section „Jak aplikacja używa tych danych” — where
  the imported data appears, what else reads it (other parts, pages, MCP), who can see it and what the import does not
  do. Each sentence was checked in the code; a new reader of a part's data belongs in that section.
- **One check for every import** (2026-11-22, `src/app/importCheck/`): `checkImport(format, doc, {base?})` runs the
  part's own planner (an adapter per MCP format id in `registry.ts` — a new import adds one line there) and returns the
  preview's lines, the deletions, and ALL errors and warnings at once. The same bundle answers MCP `check_import` on
  the server (MCP.md → Import check) and `check_import` of the local preview MCP. Identical messages are grouped
  everywhere (`core/messageGroups.ts`, `ui/MessageList.tsx`: "×N" with the single ones to unfold — messages that differ
  only in a quoted name, an `@name`, an id or a list position count as the same).
- **Checks**: `app-json-check` (pages, modules, areas, forms, calendar schemes and plans, the MCP file) and
  `app-json-parts-check` (in `npm run app:check`), which runs every `app-json-<part>-check.mjs` — a new part's check is
  picked up by its name.

What each import may do, in short (the descriptions say it in full):

- **page** — the page and its modules in place (by `id`); `"lang"` (`"en"`/`"de"`/`"pl"`, 2026-11-05) on the page
  sets the language its visitors see, on a module the language of that module; `null` or absent follows the visitor
  (page) or the page (module). Stored in the page look (`page_theme`) and the module layout (`layout.lang`).

- **liturgy** — the nine kinds of a liturgical collection by `id`: a known one changes in place (only the fields named, `null`
  clears), a new one is created, `{"id", "remove": true}` deletes (a changed built-in returns to its default); the whole
  graph is checked first and anything pointing to nothing stops the import; saved in one go with a receipt. Version 2: a
  text is one wording with its structure beside it (`layout` as pieces of the text, `layouts`, `performance`, `notes`,
  `variants`); identical wordings merge into one with aliases; earlier versions are read and migrated (LITURGY.md).
- **calendar** — appointments, series (a weekly timetable), program points, the scheme and its values, days of a series
  (cancel, restore, move, day values); deletes only with `"remove": true`; never intentions, entries, reservations.
- **masses** — masses and services (single or series, celebrants, „ta i następne” with `changeFrom`) and their
  intentions per day — the intentions book of a month; the preview says which mass gets which intention and warns
  about conflicts (by default a conflicting intention is not added); nothing is deleted (`"status": "cancelled"`).
  Scheme values (Obchód, Kolor szat) belong to `calendar`.
- **tasks** — „Tylko ja” and group tasks; `"remove": true` archives; completions are never touched.
- **bookings** — resources with their rules and offered slots; people's claims are exported for viewing only, and the
  preview warns about every collision with them.
- **chat** — the export is the whole conversation; the import never writes in someone else's name or backdates: new
  topics, new messages from the importing person (marked „Z importu”), moving to topics, pins.
- **roles** — new roles and groups under holders the account may grant, renames, kind changes, new holdings; never
  removes, never creates persons or accounts; each new role makes its keys (a few seconds each).
- **persons** — only the account's own persons, by id, field by field; an empty value never deletes (that would
  withdraw the field's releases too).
- **learn-progress** — only into one's own progress, as a new sealed batch; answers already there are skipped.
- **knowledge-base `rewards`** (2026-11-02) — Nagrody documents (points, streak, daily goal, levels, badges; `cogita/rewards.ts`),
  also edited one by one as JSON in Nauka → „Nagrody”; what a document leaves out comes from the built-in rule; the
  settings key `rewards` names the one the Nauka uses. Points themselves are never stored or imported — they are
  computed from the answers.
- **knowledge-base generators** (2026-11-03) — questions with `params` (numbers from ranges, values from a list, and
  entries: `"entry"` one, `"entries"` several, with `kind`, `rule`, `where`, `count`, `repeat`), `let`, `require`;
  `{…}` also in `correct`, `value`, `tolerance`, `unit`; templates with the node `"generate"` (the same recipe plus
  `texts` and `only`, `this` = the card's entry) and the card inputs `hints`/`solution`; answers store `seed` and
  `params`. A question's history restarts only when its recipe changes (not its prompt, hints or explanation); a
  generator with no valid instance in 60 draws makes no card and says why. Guide `guide-generators`
  (`templates/cogita/generatory-AI.md`), the four patterns as one course `example-generators`
  (`przyklad-generatory.json`).
- **knowledge-base reading tasks** (2026-11-22, Homer unit) — question forms `lines` (mark lines, `"lines": "3-5, 9"`), `label`
  (`"roles"` + `"labels": ["1: Hektor", "3-4: Achilles"]`) and `span` (`"spans": "12-15; 30-31"`) on a passage of a Library text,
  `"passage": {"work": "<id | key | @name>", "locator": "XXII 247-272"}` — the text itself never goes into the base. Lines are numbered
  1… within the passage; partial credit; `tags` as rows `"7: tag"`. A kind whose fields carry `"glossary": "word" | "forms" |
  "meaning" | "work"` is the glossary (underlined words, tap = meaning). The import warns about missing parts, unknown roles
  and tag rows without lines (`cogita/reading/readingImport.ts`); format text `cogitaDataFormat.question.body.s16Reading`.
- **knowledge-base landscape** (2026-11-03) — views with `"mode": "landscape"` and `"landscape": {"budget": 60}`
  (6–400), the condition `{"type": "knowness", "rel": "chain", "band": "known"}`; on pages the module `view` with
  `"mode": "krajobraz"` (+ `answers`, `rewards`). The goal is kept per learner and view in the learner's positions
  (`landscape:<view>`), never in the base. The import warns about prerequisite cycles touching imported entries, a
  missing axis kind and a landscape view in a base without prerequisites. How to build a base for it:
  `guide-schemes` §2.5; an example world `example-world` (`przyklad-swiat.json`) with its page `example-world-page`
  (`przyklad-swiat-strona.json`). Both can be checked before the import with `preview_knowledge` (PREVIEW-MCP.md).
- **knowledge-base whole world and parts** (2026-11-22, A2) — `"wholeWorld": true` in the head of a course: everything
  of the base the file does not contain is deleted in the same save (entries and the doc kinds of `WHOLE_WORLD_DOCS`
  in `cogita/json.ts` — templates, revisions, flows, looks, rules, values, collections, views, forms, anchors, rewards,
  paths, units; never kinds, settings, feedback, learner data). It runs through the ordinary removals (`plan.removals`,
  `removalEffects`): the first preview line says how many, each is listed and can be unticked, a flow/view that still
  points at one blocks the save. Items the file points at without containing them stay (warning). `"part": "<name>"`
  stamps `_part` on every entry (mark) and doc (data) the file creates or changes, also unchanged ones (bookkeeping
  save); with `wholeWorld` only that part's items are deleted, items of no part stay (counted). An export re-imported
  as a whole world deletes nothing. Checks: `app-import-check` §7.
- **knowledge-base view: part of the world** (2026-11-24) — a world view (`"landscape": {"style": "world"}`) may carry
  `"only": {"tags": ["@…"], "places": ["@…"], "withBase": true}`: the map shows only those towers (tags with their subtags, plus,
  by default, every prerequisite); refs go out as `@name` and come back resolved (unknown ones are reported). A view with
  `"forClass": "<class area id>"` is the part of the world a teacher set for a class (`classes/subWorld.ts`).
- **knowledge-base size** (2026-11-22, A4) — up to 20 000 items incl. removals per save (`SAVE_ALL_MAX`), ~150 MB
  sealed. `putEntries` splits anything above 2000 items or 16 MB of envelopes into parts: `POST …/entries/save/stage`
  (table `app.library_save_stage`, migration 0143; parts expire after one hour) and a final `POST …/entries/save` with
  `"stage"` that writes all parts in ONE transaction with the same checks (versions, library, removals) — all or
  nothing; the parts are deleted with it or on failure. Each request stays under the IIS limit (30 MB). Checks:
  `app-import-check` §8, Api.Tests `LibraryChecks` (stage), LocalDB drive (A4 session scratchpad `a4/drive.mjs`, 13).
- **knowledge-base `units`** (2026-11-22, Homer) — lesson units: several lessons as one list of stages
  (`cogita/unit/unitModel.ts`): `{ref, name, lessons: [{title}], stages: [{id, lesson, title, type core|flex|close,
  minutes [min,max], modes ["P","V","R","I","O","Q","X"], led?, order fixed|free, items, bonus?, skipIf?}], settings?}`;
  items `{flow, start?}` · `{questions: [@q…]}` · `{prompt, max ≤ 80, anonymous}` · `{poll, options, id?, after?}`.
  Refs resolve like every doc (`flow` a flow, `questions` entries); an unknown flow/question, an unreadable item or a
  stage id twice blocks the save (`unitIssues`), a lesson without `close` or a core over ~40 min warns. Part of
  `WHOLE_WORLD_DOCS`. Example `example-unit` (`templates/cogita/przyklad-jednostka.json`). Checks: `app-unit-check`.
- **lamps** — lamps, signals, timers and the button pace; deletes only with `"remove": true`.
- **addresses** — aliases and domains the app can set; the preview lists what remains outside (DNS, hosting, the
  service's origins).

## Checked in a browser

`scratchpad/…/argdesign/json-parts-browser.mjs` (LocalDB only, after `json-api.mjs`) opens every panel the way a
person does and walks it: export, the unchanged export back (no change), a sample imported, export again, and that
export — now with real content — back once more (still no change).

## Without import, on purpose

- **Sprawy** (reports): a report is a sealed letter in a signed chain (REPORTS.md); nothing is made from a file.
- **Konto keys, access links, AI links, seats**: they are secrets or made from secrets in the browser.
- **Administrator danych**: signed by a role with its certificate (DATA-CONTROLLER.md) — typed and signed in place.
