# REcreatio

A platform for parishes and communities: pages, forms with people and their steps, calendars and masses, bookings,
chats, a library and Cogita (learning). Everything personal is encrypted in the browser; the service stores
ciphertext and checks signatures, it never holds the keys.

- Website: <https://recreatio.pl> (GitHub Pages, from `docs/`)
- Service: `api.recreatio.pl` (ASP.NET Core on Webio)
- Android app: the same web bundle in a Capacitor shell (`frontend/android/README.md`)

## Repository

```
backend/
  Api/              the service (.NET 10, minimal APIs, namespace Api), one folder per domain:
                    Identity, Roles, Areas, Pages, Forms, Calendar, Bookings, Masses, Chat,
                    Library, Cogita, Notifications, Registry, Infrastructure, Transfer
    Sql/            migrations 0000–NNNN, embedded and run by `migrate`; diagnostics/ (read-only checks)
  Api.Tests/        service checks (console program)
  Kernel/           cryptography and canonical forms shared by the service (AES-GCM, RSA, AAD, records)
  Kernel.Tests/     kernel test vectors
frontend/
  src/app/          the application (React 18 + TypeScript), one folder per domain — see documentation/ARCHITECTURE.md
  src/legacy/       six content files the fixture generators still read (scripts/cogita-home.mjs, presentation-home.mjs)
  scripts/          checks (`app-*-check.mjs`), fixture generators, Android build and upload
  public/           static files served as they are (widget.js, legal pages, logos)
  android/          the Capacitor Android project
documentation/      ARCHITECTURE.md, TRANSFER.md, COGITA.md, LIBRARY.md, CHAT.md
docs/               the built website (generated by deploy-web.bat — do not edit)
deploy-web.bat      builds the frontend and replaces docs/
deploy-app.bat      builds the Android app (APK, AAB) and uploads to Google Play
```

## Running locally

The development service talks to the production database (connection string in `dotnet user-secrets` of
`backend/Api`). Test data is created as `zz-probe-…` and removed afterwards.

```sh
dotnet run --project backend/Api                 # service on http://localhost:50994
npm --prefix frontend install
npm --prefix frontend run dev                    # Vite on http://localhost:5173, /api proxied to the service
```

`VITE_APP_API_ORIGIN` points the dev server at another service port.

## Checks

```sh
npm --prefix frontend run app:check              # type check of the whole src + the app-*-check scripts + the style ratchet
npm --prefix frontend run build                  # production bundle
dotnet build recreatio.sln
dotnet run --project backend/Api.Tests
dotnet run --project backend/Kernel.Tests
```

The style ratchet (`scripts/app-style-check.mjs`, baseline in `scripts/style-baseline.json`) only lets the counts
of hand-made values fall; after an improvement, lock it in with `node scripts/app-style-check.mjs --update`.

## Database migrations

```sh
dotnet run --project backend/Api -- migrate --dry-run            # what would run
dotnet run --project backend/Api -- migrate                      # apply and record
dotnet run --project backend/Api -- migrate --record-through 0111 # record scripts that were applied by hand
```

Applied scripts are never edited (the checksum is recorded); changes go into a new script. `0000_*` scripts are
destructive and run only with `--drop-legacy`. See documentation/TRANSFER.md for the current state.

## Deploying

- Website: `deploy-web.bat`, then commit and push `docs/`.
- Service: publish `backend/Api` with the Webio profile (`dotnet publish backend/Api -p:PublishProfile=Webio -p:IsGetPasswordEnabled=true`); `appsettings.Production.json` stays on the server.
- Android: `deploy-app.bat` (signing key and Play service account under `%USERPROFILE%\.recreatio\android`).
