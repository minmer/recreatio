# Publishing REcreatio on Google Play

This page covers everything Google Play asks for, and where each answer comes from. The texts and images live next to it:

- `listings/pl-PL/*`, `listings/en-US/*`: title, short and full description, and in `pl-PL/images` the icon, feature graphic and 6 phone screenshots.
- `release-notes/*.txt`: "What's new" for the next release. Update these before each release.

The scripts that use them:

| Command | What it does |
| --- | --- |
| `npm run android:release` | Builds the APK and AAB into `frontend/android-out/`. |
| `npm run android:publish` | Uploads the newest AAB to Play: internal testing, as a draft. |
| `npm run android:publish -- --listing-only` | Uploads only the texts and images. |
| `deploy-frontend.bat` | Deploys the website, builds the app from the same build, and uploads it if the service account exists. |

## Before the first upload

Do these in this order:

1. **Deploy the API.** It contains account deletion (`AccountDeletion.cs`). Use the usual Webio publish (`-p:PublishProfile=Webio -p:IsGetPasswordEnabled=true`).
2. **Deploy the website** (`deploy-frontend.bat`, then commit and push `docs/`). It brings three things online:
   - `https://recreatio.pl/prywatnosc/`, the privacy policy. **Have the parish review it**: controller, age limit, contacts.
   - `https://recreatio.pl/usun-konto/`, the account deletion page.
   - `https://recreatio.pl/.well-known/assetlinks.json`, so recreatio.pl links open in the app. `public/.nojekyll` makes GitHub Pages serve the dot-folder.
3. **Check the review account.** Its credentials are in `~/.recreatio/android/play-review.txt`: account `demo`, with sample groups, events, tasks and a chat. The screenshots were taken with it. Keep it, because Google reviews every update with it.

## Play Console, step by step

### 1. Create the app
- Name: **REcreatio**
- Default language: **Polish (pl-PL)**
- App or game: **App**. Free or paid: **Free**.
- Confirm the declarations (Developer Program Policies, US export laws).

### 2. App signing
Accept **Play App Signing** with a key generated by Google. The key in `~/.recreatio/android` then becomes the **upload key**; `npm run android:release` already signs the AAB with it.

After enrolling, go to *Setup → App integrity* and copy the *App signing key certificate* SHA-256. Add it as a second entry in `public/.well-known/assetlinks.json`, then redeploy the website. Otherwise links do not open in the Play-installed app.

Installs from Play and installs of the APK you build yourself are signed by different keys. Switching between the two means uninstalling once.

### 3. First release (by hand)
The API cannot create an app, so the very first AAB is uploaded manually:

1. Open *Testing → Internal testing* and create a new release.
2. Upload `frontend/android-out/recreatio-<version>.aab` and paste the release notes.
3. Add testers (an e-mail list) and roll out.

**New personal developer accounts** (created after 13 Nov 2023) must run a closed test with at least 12 testers for 14 days before they may publish to production. Organisation accounts are exempt. Check what your account shows under *Dashboard*.

### 4. Main store listing
Copy the fields from `listings/`, or upload them with `npm run android:publish -- --listing-only` once the service account exists.

- Category: **Social**. *Productivity* is the alternative.
- Contact e-mail: `kontakt@recreatio.pl`. Website: `https://recreatio.pl`.
- Upload the icon (512×512), the feature graphic (1024×500) and the phone screenshots (1080×1920) from `listings/pl-PL/images/`.

### 5. App content
| Section | Answer |
| --- | --- |
| Privacy policy | `https://recreatio.pl/prywatnosc/` |
| App access | *All or some functionality is restricted.* Instructions: "Log in with the account below. Everything else is reachable from the Warsztat (workspace) screen." Credentials from `play-review.txt`. |
| Ads | No ads. |
| Content rating (IARC) | Category *Social / communication*. Violence, sexuality, language, drugs, gambling: **no**. Users can interact and exchange content: **yes**. Shares location: **no**. Digital purchases: **no**. |
| Target audience | **16–17 and 18+.** The app is not designed for children. If you choose an age group under 13, the Families policy applies. |
| News app | No |
| Health / financial features / government app | None / no |
| Advertising ID | The app does **not** use the advertising ID. |
| Account deletion | In the app: **yes** (Konto → Usunięcie konta). Web link: `https://recreatio.pl/usun-konto/` |

### 6. Data safety
Google does not count data as "collected" when it leaves the device end-to-end encrypted, so that nobody but sender and recipient can read it. **Check the current wording in the Play Console help when you fill this in.** If unsure, over-declare: that is allowed, under-declaring is not.

**Collected** (the service can read it):

| Data type | Purpose | Optional? |
| --- | --- | --- |
| Personal info → **User IDs** (account name) | App functionality, account management | Required |
| App activity → **Other user-generated content**: group names, event times and public titles, bookings, message metadata | App functionality | Required |
| App info and performance → **Diagnostics**: IP address in server logs | Security, fraud prevention | Required |

**End-to-end encrypted** (not collected as defined by Google): names and personal data, message content, photos, files and voice messages, private event details, tasks, form answers.

The remaining questions:

| Question | Answer |
| --- | --- |
| Data shared with third parties? | **No.** Hosting (Webio) is a service provider, not "sharing". |
| Encrypted in transit? | **Yes** (HTTPS only). |
| Can users request deletion? | **Yes**, in the app and at `https://recreatio.pl/usun-konto/`. |
| Processed ephemerally? | No. |

## Automatic uploads (after the first release)
1. **Google Cloud Console.** Create a project (or use an existing one) and enable the **Google Play Android Developer API**.
2. **Service account.** Create one (no roles needed in Cloud), add a **JSON key** and save it as `~/.recreatio/android/play-service-account.json`. Never put it in the repo; `$RECREATIO_PLAY_KEY` can point elsewhere.
3. **Play Console → Users and permissions.** Invite the service account's e-mail and, for the app REcreatio, grant:
   - *Release apps to testing tracks*;
   - *Manage store presence*, needed for `--listing`;
   - optionally *Release to production*.
4. **Test it** with `npm run android:publish -- --dry-run`, then `npm run android:publish`.

After that, `deploy-frontend.bat` builds and uploads to **internal testing as a draft** on every deploy. You roll it out in the console, or directly with:

```sh
npm run android:publish -- --status=completed                        # internal testing, live for testers
npm run android:publish -- --track=production --status=completed     # production (after review access)
npm run android:publish -- --listing                                 # also update texts and images
```

## Every update
1. If the backend changed, deploy the API first. The app carries its frontend and needs the matching API.
2. Update `release-notes/pl-PL.txt` and `release-notes/en-US.txt`.
3. Run `deploy-frontend.bat`, then commit and push `docs/`. The version number rises by itself (minutes since 2026).
4. Roll out the draft in the Play Console, or promote it from internal to production.
